# Internal implementation contract

All API routes below use `/api`; JSON uses snake_case; monetary values are integer cents. Errors use `{detail: string}`. Cookie `permits_session`; GET `/auth/me` returns `{user, csrf_token, demo: true}`. Login body `{email,password}` returns same; logout POST requires CSRF. Mutations include `X-CSRF-Token`. User: `{id,name,email,role,municipality_id}`. Roles admin, clerk, reviewer, inspector, applicant. GET `/health` public.

DB connection helper `backend.db.connect()` returns sqlite3 connection with Row factory, FK enabled; use `with connect() as db` transactions. `backend.security.current_user(request)` dependency returns dict user. `require_roles(user,*roles)` raises HTTPException. `get_permit(db,id,user)` returns scoped Row or 404. `audit(db,user,entity,entity_id,action,details)` inserts audit. `now()` UTC string. `backend.db.initialize()` migration + `seed_demo()` when enabled. Modules: root agent owns main.py, security.py, core.py and tests; backend agent owns db.py, migrations, workflows.py and workflow tests; frontend agent owns frontend only.

Tables (backend agent defines exact schema following these columns): municipalities(id,name); users(id,name,email,password_hash,role,municipality_id); sessions(token_hash,user_id,csrf_token,expires_at); applicants(id,municipality_id,name,email,phone); contractors(id,municipality_id,name,license_number,email); permit_types(code,label,base_fee_cents,area_rate_cents); statuses(code,label,next_statuses JSON text); permits(id,number,municipality_id,owner_id,applicant_id,contractor_id nullable,type,status,description,work_address,area_sqft,prior_approval INTEGER,fee_cents,exempt INTEGER,exemption_reason,created_at,updated_at); plan_reviews(id,permit_id,reviewer_id,result,notes,created_at); inspections(id,permit_id,inspector_id,scheduled_date,status,result,notes,follow_up,created_at); payments(id,permit_id,amount_cents,method,reference,idempotency_key UNIQUE,request_hash,reconciled INTEGER,created_at); certificates(id,permit_id,number,status,created_at,revoked_at); notices(id,permit_id,kind,description,deadline,status,created_at); audit_log(id,municipality_id,user_id,entity,entity_id,action,details,created_at). Store fixed declared fee rules, statuses and demo user hashes using security.hash_password from seed function import at call time (avoid import cycle).

Demo users `admin@demo.permitsnj.test`, `clerk@demo.permitsnj.test`, `reviewer@demo.permitsnj.test`, `inspector@demo.permitsnj.test`, `applicant@demo.permitsnj.test` in municipality 1; `other@demo.permitsnj.test` admin municipality 2. Password `DemoPermit2026!` only in explicit DEMO_MODE. Seed names: municipality 1 `Maple Harbor (Demo)`, municipality 2 `Cedar Borough (Demo)`. Sample permits and records should be synthetic. Set seed data only once. DB path `DATABASE_PATH` default `./data/permitsnj.sqlite3`; DEMO_MODE default false, must opt in. `SESSION_SECURE` env default true, explicit false localhost demo.

Core routes: GET `/config` returns `{permit_types,statuses,municipalities,users}` (users excludes hashes and only same municipality); GET `/permits?q=&status=&type=&sort=updated_at&direction=desc&page=1&page_size=10` returns `{items,total,page,page_size}` with each item including `paid_cents,balance_cents,applicant_name,contractor_name,municipality_name`; GET `/permits/{id}` same enriched permit plus `plan_reviews,inspections,payments,certificates,notices,audit`; POST `/permits` body `{applicant_id,contractor_id?,type,description,work_address,area_sqft,prior_approval}`; PATCH `/permits/{id}` same partial fields; POST `/permits/{id}/status` `{status}`; POST `/permits/{id}/exemption` `{exempt,reason}`; POST `/permits/{id}/transfer` `{municipality_id,applicant_id,contractor_id?}` admin only. GET `/dashboard` returns `{permit_count,open_count,outstanding_cents,inspections_due,recent_permits}`. GET/POST `/applicants`, `/contractors`; GET `/municipalities`. Directory lists return arrays. GET/POST `/statuses` admin writes `{code,label,next_statuses:[...]}`.

Workflow routes (backend agent): GET `/payments`, `/plan-reviews`, `/inspections`, `/certificates`, `/notices` return scoped arrays including `permit_number` and `work_address`; POST `/permits/{id}/payments` `{amount_cents,idempotency_key,simulate_failure?:false}` returns payment (201, replay 200), mock method only; POST `/payments/{id}/reconcile` staff; POST `/permits/{id}/plan-reviews` `{result:approved|changes_requested,notes}`; POST `/permits/{id}/inspections` `{inspector_id,scheduled_date}`; PATCH `/inspections/{id}` `{result:passed|failed,notes,follow_up}`; POST `/permits/{id}/certificates` {}; POST `/certificates/{id}/revoke` {}; GET `/certificates/{id}/document` printable HTML; POST `/permits/{id}/notices` `{kind:notice|order,description,deadline}`; PATCH `/notices/{id}` `{status:resolved}`; GET `/notices/{id}/document`. GET `/reports?date_from=&date_to=&municipality_id=` returns `{summary:{permit_count,assessed_cents,paid_cents,balance_cents},items:[...]}`; GET `/reports/export` same filters CSV. GET `/audit` scoped list latest 100, staff only. All mutations CSRF middleware root agent. Staff allowed: payments reconcile admin/clerk; review admin/reviewer; inspection schedule admin/clerk and result admin/assigned inspector; certificates/notices admin/clerk; reports/audit all staff.

Frontend: use relative `/api`, Vite proxy localhost:8000. API defaults port 8000 and serves frontend/dist on production. Use CSS and inline SVG icons (lucide-react optional), no external assets needed. Label demo everywhere; never ask for card data. Login screen quick demo role selector; real email/password form. Pages: Dashboard, Permits (list + drawer/detail/form), Applicants, Contractors, Municipalities, Payments, Plan Reviews, Inspections, Certificates, Notices & Orders, Reports. Detail workflow forms call above endpoints and refresh. Applicant self-owned records only.
